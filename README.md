# Клуб 7:00

Сайт командного челленджа пунктуальности. Создан в Codex, без Lovable. React/Vite, Node.js 24, PostgreSQL для бесплатного размещения (Neon), SQLite для локальной разработки.

## Бесплатное размещение: Render + Neon

Код и готовые настройки находятся в этом репозитории. Публикация требует ваших аккаунтов хостинга; никаких секретов в чате или GitHub хранить не нужно.

1. Откройте https://console.neon.tech и создайте бесплатный проект **Free**, например `club-700`. Сохраните строку подключения из **Connect** (PostgreSQL connection string). Это пароль к базе: не отправляйте её в чат и не публикуйте.
2. Откройте https://dashboard.render.com и войдите через GitHub. Выберите **New → Blueprint**, подключите репозиторий `JuLuVik/club_boorun`. Render прочитает `render.yaml`.
3. В параметрах задайте две переменные: **DATABASE_URL** — строка подключения из Neon; **COACH_PIN** — ваш собственный код из 6–12 цифр. Тариф сервиса в конфигурации — **Free**; платный диск не нужен.
4. Нажмите **Deploy Blueprint**. После успешной сборки Render покажет публичный HTTPS-адрес сервиса. Название адреса назначает Render; заранее оно не гарантируется.
5. Откройте адрес, нажмите **Я тренер**, введите свой PIN, добавьте участников. Сделайте отметку, сохраните её и обновите страницу для проверки.

На бесплатном тарифе Render сервер засыпает без посещений; первое открытие может занять около минуты. Neon также может приостанавливать вычисления без нагрузки, но база сохраняется отдельно. Бесплатные тарифы имеют ограничения и могут меняться — проверьте, что выбраны именно **Free**. Если интерфейс предлагает оплату, не продолжайте с платным тарифом.

Данные хранятся в PostgreSQL и сохраняются при перезапусках и новых размещениях сервера. Не удаляйте проект Neon. Клиенту не передаётся строка подключения или PIN. TLS базы проверяется с `sslmode=verify-full`; проверка сертификатов не отключается.

Если пункт Blueprint недоступен, создайте **New → Web Service**, выберите этот репозиторий, runtime **Node**, plan **Free**, build command `npm ci && npm test && npm run build`, start command `npm start`. Добавьте `NODE_ENV=production`, `NODE_VERSION=24.19.0`, `DATABASE_URL`, `COACH_PIN`, health check `/api/health`.

## Разработка

```sh
npm ci --cache /tmp/club-npm-cache
npm run dev
```

Node.js 24; интерфейс на 5173, API на 3001. Локальный PIN по умолчанию **0700**, только для разработки. SQLite: `.data/club.sqlite`. Для PostgreSQL задайте `DATABASE_URL` перед запуском. Переменные для локального сервера задаются в процессе оболочки; `.env` автоматически не загружается.

В production обязательны собственный PIN из 6–12 цифр и `DATABASE_URL` (либо `DB_PATH` на постоянном диске). Сервер откажется запускаться без постоянного хранилища. Сессия тренера хранится в памяти сервера 8 часов; после перезапуска нужен повторный вход. Неверные попытки PIN ограничены пятью в минуту глобально для одного экземпляра сервера.

## Правила

- Вовремя: +1 к серии; опоздание: сброс; пропуск: не меняет серию и процент.
- Процент = вовремя / (вовремя + опоздания). При отсутствии посещений — «—».
- Рейтинг: текущая серия, затем процент, затем имя.
- Значки за лучшую серию: 3, 5, 10, 20; не теряются при последующем опоздании.
- Коррекция старых отметок пересчитывает историю и значки по датам.
- Пунктуальность команды — все посещения текущего календарного месяца (по времени браузера), а не среднее процентов участников.
- Повторное нажатие выбранного статуса снимает отметку после сохранения. Отметка уникальна для участника и даты.
- Удаление участника удаляет историю только после подтверждения.
- Пока команда пуста, рейтинг показывает явно подписанный пример. Он не сохраняется в базу и не смешивается с настоящими данными.

## Проверки

```sh
npm test
npm run build
node tests/browser.mjs
```

Браузерный тест требует Chromium (`/usr/bin/chromium` или `CHROMIUM_PATH`), использует изолированную временную SQLite и порт 3101. Для проверки PostgreSQL выполните `TEST_DATABASE_URL=... node --test tests/postgres.mjs` на **отдельной тестовой базе**. Не используйте рабочую базу: тест создаёт и удаляет собственные записи.
